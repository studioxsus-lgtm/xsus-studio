# Phase 49 — Trusted host agent contract

This module defines a host-side coordinator for fenced launch/stop/cleanup. The injected `withExclusiveExecutionLock` must serialize actions for each execution across processes and hold the lock until the action and receipt write complete. The agent checks the persisted fence, rejects stale tokens, advances the fence before acting, and requires a confirmed physical action and durable receipt before acknowledgement.

**Not production-ready:** This is a contract-based coordinator, not a running host daemon. The lock, durable fence ledger, physical executor, and receipt store are injected; mocks are used in tests. Equal-fence actions are not idempotent and must be prevented by a durable operation ledger. This module does not validate active PostgreSQL leases or host identities; the caller must authenticate and authorize each operation. A crash after physical action but before receipt creates an ambiguous outcome requiring reconciliation, not blind retry. A cross-host lock or globally authoritative fencing boundary is necessary if multiple hosts can operate on one execution. The fencing ledger must be durable and must not be reset. Do not expose Docker or host credentials to browser clients. No real Docker or database integration has been performed.
