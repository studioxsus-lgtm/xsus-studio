# Phase 42 — Runtime execution binding

The backend-only coordinator binds the audited lifecycle to the isolated executor. It authorizes requests before registration, registers and starts an execution, invokes the isolated runtime, and records a terminal state. Runtime errors are not treated as success. Inspection requires authorization. Cleanup can only be marked after an injected trusted host verifier confirms a receipt against the execution's revision and fence.

**Security and correctness limits:** Authorization and cleanup verification are injected contracts, not implemented identity or host attestation. The coordinator does not run Docker itself and does not provide durable scheduling, retries, heartbeat leases, process crash recovery, or proof that a host actually cleaned resources. A failure between registration/start/runtime and terminal recording may leave a nonterminal state. A thrown terminal transition requires reconciliation; it must not trigger blind re-execution. The host cleanup receipt and fencing must be independently verified before production use. The test suite uses mocked lifecycle and executor components and does not prove production isolation.
