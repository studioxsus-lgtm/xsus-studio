# Phase 47 — Database-time lease acquisition and renewal

This backend-only module implements atomic PostgreSQL acquisition (single-statement INSERT ON CONFLICT DO UPDATE), renewal (conditional UPDATE), and release (fenced UPDATE). Acquisition and renewal use `clock_timestamp()` on the database server. Expired leases can be taken over with an incremented fence; active leases cannot be replaced. The schema is the existing draft `postgres-lease-schema.sql`.

**Security constraints:** Only a dedicated trusted backend role should call these operations. The database lease fence and lifecycle revision/fence are separate. A lease takeover does not prove the previous container stopped; do not launch a replacement without host-enforced fencing or independently verified termination. Host-side action boundaries still need atomic fencing checks. This implementation does not run migrations, grant privileges, or connect to live PostgreSQL. Unit/integration tests use mocked SQL responses, not a real database. Database BIGINT values above JavaScript safe integer range fail closed. No retry should be performed after an ambiguous transport or commit outcome without reconciliation.
